# Release Rollback

## Когда использовать
- После релиза вырос error rate
- Появились массовые жалобы пользователей
- Сервис деградировал сразу после выкладки

## Признаки
- Корреляция по времени между релизом и инцидентом
- Ошибки только в новой версии
- После переключения трафика начались сбои

## Что проверить
1. Время начала инцидента
2. Какие сервисы были задеплоены
3. Какие feature flags были изменены
4. Есть ли ошибки только на новой версии
5. Есть ли план отката и совместимость схем

## Порядок действий
1. Оценить масштаб влияния
2. Принять решение: rollback или hotfix
3. Если rollback безопасен, вернуть предыдущую стабильную версию
4. Проверить состояние сервиса после отката
5. Сообщить команде о результате

## Важно
- Проверить миграции БД перед откатом
- Проверить совместимость старого кода с новыми данными
